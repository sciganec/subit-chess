## Що в релізі

Детермінований пошук і справжній максимальний рівень. Обидва пункти виросли з одного
скарга-звіту («здається, двигун став слабшим») і його вимірювання.

- **Хід у корені залежав від того, що шукали раніше.** TT писав `generation` для кожної
  позиції, але `probe()` його ніколи не читав, тож межа, записана за одного порядку
  ходів, перевикористовувалась у наступних пошуках і могла перекинути вибір у корені:
  після 11...O-O холодний пошук `d12` давав Kxf1 +81.0, а той самий пошук після
  `d6/d8/d10` — Nf5 +113.2 (свінг 32 cp із застарілих записів, а не з позиції).
  Записи старші за одну генерацію тепер ігноруються (`TT_MAX_AGE`).
- **Максимальний рівень шукав 8 ply.** На позиції після 11...O-O рушій тримає той самий
  хід (Kxf1) від d8 до d12, але його рахунок іде 0.0 → +12.0 → +135.0 → +81.0: на ігровій
  глибині він показував рівність там, де виграє. Рівень 5 тепер `depth: 10` із
  6-секундним годинником. Це піднімає загальну глибину, але **не** робить рахунок тієї
  партії точним — для цього потрібні d11, ≈13 с, чого браузер не може собі дозволити.
- **Пігулка рівня показує реальну глибину** (`Рівень 3 · d4`), а не номер рівня.

## Перевірка

```
npm run build     # детерміновано: той самий файл байт-у-байт
npm test          # exit 0: core.perft, smoke, plans, eval, verify, driver, learn, app.dom
npm run test:legacy  # 128 passed, 0 failed (v2.2.0, для референсу)
```

Регресії (`tests/engine.eval.mjs` §12): свіжий запис TT проб'ється, запис віком одну
генерацію — теж, дві генерації — ні; той самий хід у корені після `d5/d7` та без них;
межа `TT_LOWER`/`TT_UPPER` не публікується як точний рахунок.

perft без змін: startpos `20 / 400 / 8902 / 197281`, Kiwipete `d3 = 97862`.

## Виміряна сила (чесно)

Це реліз відтворюваності й глибини, не оцінки. Ціна старіння TT — 2.29M вузлів проти
2.24M на лінії з 22 півходів при 600 ms/хід (+2%) і жодної втрати досягнутої глибини
(150 проти 149 холодний, 159 проти 159 теплий). Жодного вимірювання сили, що підтверджує
або спростовує зміну, немає.

Що **не** є регресією: v3.0.0 і v3.0.3 повертають ідентичні ходи й рахунки на критичній
позиції (Kxf1 0.0 / 12.0 / 81.0 на d8/d10/d12). Зміни між релізами (futility, aspiration,
повторення) цю лінію не торкнулися.

Хід у тій партії ніколи не був проблемою: власний глибший пошук рушія на кожній глибині
віддає перевагу Kxf1, а людський 12.Nf5 оцінювався +113 лише поки в TT лежали застарілі
записи. Зі старінням той самий пошук дає Kxf1 (+135 на d11).

## Відомі прогалини (з аудиту v3.0.2, не в цьому релізі)

- Валідація FEN (символи, довжина рядків, наявність королів, коректність ep/рокірувань).
- Quiescence не бачить пат/нічию на горизонті (лише взяття та перетворення).
- Метаконтролер обходиться при фіксованій глибині (UI передає `depth`, а не лише час).
- Немає Web Worker: пошук блокує UI-потік, а рівень 5 може тримати його до 6 с.
- Мертвий `contextBonus` в `index.mjs` (завжди 0) і `Score.diff`, який ніхто не пише.
