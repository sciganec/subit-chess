## Що в релізі

Виправлення стану партії. Усі три дефекти невидимі в тестах, бо проявляються лише в
справжній партії, а не в одному пошуку.

- **Партія втрачала історію повторень після кожного ходу.** `Engine.play()` перезбирав
  позицію через `setFEN()`, який чистить `rep`/`repLimit`, тому поза межами одного пошуку
  повторення не бачились узагалі: ні заявити нічию на трьохкратному, ні уникнути її, а
  рівні позиції йшли до 300-півневого cap. Тепер `play()` зберігає стек (і фіксує позицію,
  яку залишає).
- **Повторення зіставлялися лише за 32 бітами** (`hashLo`): колізія могла завершити
  виграну партію як нічию. Тепер порівнюються обидві половини Zobrist-ключа.
- **Ліміт вузлів тихо губився.** `Engine.search()` викликав `setLimits({nodes})`, а потім
  `searcher.search(pos, {depth, timeMs})`, і саме з цих опцій пошук перечитує ліміти:
  `search({depth: 8, nodes: 1})` раніше обробляв 81 619 вузлів. Тепер бюджет їде разом із
  викликом (`nodes: 1` → 1 вузол).
- **Перемикач fast/structural не працював.** `Engine.search()` перепризначав
  `evaluation.opts.mode` з дефолтів на кожному виклику, тож вибір у UI зникав. Рівень
  тепер обирає лише метаконтролер, `Engine.setEvalMode()` зберігає явний вибір, і UI
  користується ним.

## Перевірка

```
npm run build     # детерміновано: той самий файл байт-у-байт
npm test          # exit 0: core.perft, smoke, plans, eval, verify, driver, learn, app.dom
npm run test:legacy  # 128 passed, 0 failed (v2.2.0, для референсу)
```

Регресії (`tests/engine.eval.mjs`): чотири цикли `g1f3 g8f6 f3g1 f6g8` → `repetitionCount() = 5`
і `status() -> fivefold repetition`; `search({depth: 8, nodes: 1})` → 1 вузол.

perft без змін: startpos `20 / 400 / 8902 / 197281`, Kiwipete `d3 = 97862`.

## Виміряна сила (чесно)

Це реліз коректності, не сили. Розуміння повторень прибирає сліпе перемішування, але
вимірювального приросту рахунку поки немає: `base` vs `futil3` при 150 ms/хід, 24 партії —
47.9% ± 16.1 (7W 9D 8L), тобто в межах шуму. Глибина за фіксованої 1 с на позицію однакова
для обох конфігурацій (kiwipete d5, ендшпіль d8, ~150k вузлів), тому 3x вартість вузлів
виправлення futility з 3.0.1 проявляється лише при фіксованій *глибині*.

## Відомі прогалини (з аудиту v3.0.2, не в цьому релізі)

- Валідація FEN (символи, довжина рядків, наявність королів, коректність ep/рокірувань).
- Quiescence не бачить пат/нічию на горизонті (лише взяття та перетворення).
- Метаконтролер обходиться при фіксованій глибині (UI передає `depth`, а не лише час).
- Немає Web Worker: пошук блокує UI-потік.
- 32-бітові ключі repetition виправлено, але Zobrist-генератор (xorshift32) варто
  замінити на 64-бітний.
