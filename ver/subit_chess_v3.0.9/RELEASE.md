## Що в релізі

Коректний інкремент: закрито шість P0-дефектів з
`ver/subit_chess_v3.0.8/subit_chess_v3.0.8_audit_2.md` (AUD-01…AUD-06). Це виправлення
коректності, **не** заява про силу гри: оцінка не змінюється на краще чи гірше, вона
перестає публікувати рахунок із позицій, які не були знайдені легальним ходом.
Інтерфейс не змінився; файл, як і раніше, один офлайн-HTML.

### Виправлено

- **AUD-01 — stand-pat у шаху.** `quiescence` повертав статичну оцінку позиції з шахом
  і міг відрізати її за beta. Статична оцінка не є легальним ходом: тепер вузол починається
  з `-INF`, і межу встановлює перший знайдений вихід із шаху.
- **AUD-02 — кап глибини qsearch у шаху.** На межі глибини стару оцінку незавершеного
  шаху (або `-INF` із хибною поразкою) замінено на `staticCheckEvasion()`: робиться один
  легальний хід-відповідь, і оцінюється вже досягнута позиція (мата немає, якщо виходу
  немає). Рекурсії немає — кап лишається капом.
- **AUD-03 — пат на горизонту на будь-якій глибині.** Перевірка пату більше не працює
  лише при `qdepth === 0`: вона виконується, коли не згенеровано взять, тому глибший
  тихий горизонт не може видати матеріальний рахунок за нічийну позицію.
- **AUD-04 — нічийні за вимогою лишаються грабельними.** `negamax` вважає термінальними
  лише автоматичні нічиї (75 ходів, п'ятиразове повторення). Вимоги 50 ходів і триразового
  повторення — звичайні позиції, згідно з ADR 0020. Це скасовує частину ADR 0011 про
  пошук; частина про статус гри лишається чинною.
- **AUD-05 — корінь поважає автоматичні нічиї.** `search()` виявляє правило 75 ходів,
  п'ятиразове повторення й недостатню кількість матеріалу до пошуку й повертає термінальний
  результат із `reason`, що збігається з `Position.status()`.
- **AUD-06 — знак у futility.** Статична оцінка після ходу береться з протилежним знаком
  перед порівнянням з alpha (позиція належить супернику); старий знак відсікав саме ті
  тихі ходи, які слід було зберегти.

### Змінено

- **Термін дії TT звужено до одного пошуку.** `TT_MAX_AGE = 0`, і `ttMoveFor()` застосовує
  той самий віковий фільтр, що й `probe()`. Після виправлення quiescence застаріла підказка
  ходу переставляла дерево й змінювала опублікований рахунок (холодний `-3`, теплий `+25`
  на позиції ADR 0011). Ітеративне поглиблення не страждає — усі його записи мають одне
  покоління — а `Memory` й далі переносить хід і рахунок між ходами партії. Див. ADR 0022.

### Додано

- `tests/engine.audit2.mjs` — 12 перевірок, по одній і більше на кожен P0-дефект;
  підключено до `npm test`, `npm run test:engine` і `npm run test:audit2`.
- **ADR 0022** у `docs/DECISIONS.md` — рішення про термінальну коректність пошуку.

## Перевірка

```
npm run build        # детерміновано: той самий файл байт-у-байт
npm test             # exit 0, включно з AUDIT2: ALL CHECKS PASSED
npm run test:legacy  # референс v2.2.0
```

Тест холодно/теплого пошуку (`tests/engine.eval.mjs` §12) знову проходить: однакові
рахунок і хід незалежно від того, які мілкі пошуки запускалися раніше.

## Що лишилося (не в цьому релізі)

- AUD-07…AUD-09 (забруднення історії повторень null-ходом, мертвий матеріал на горизонту,
  еквівалентність стану після null-ходу) — відкриті P1.
- P3.2–P3.6 (self-play цикл, контроль параметрів, незалежний validation set, порівняння
  версій, вимірювання сили) обслуговуються `bench/match.mjs`, `engine.learn` і `selfplay`,
  але ще ні разу не запускалися на вибірці, якої вимагає Gate 1.
