## 1. Швидкий старт

Відкрийте файл `src/subit_chess_v3.0.1.html` у браузері (подвійний клік працює: файл
самодостатній, без мережі, без CDN, без збірки).

```
1. Ви граєте білими, двигун — чорними.
2. Натисніть на фігуру → підсвітяться легальні поля (крапки) та бої (кільця).
3. Натисніть на підсвічене поле — хід зроблено. Альтернатива: перетягнути фігуру.
4. Праворуч одразу оновлюються панелі: S₀, SVF, плани, відношення, пошук.
5. ⚡ Нова гра починає партію заново, ↶ Скасувати відкочує вашу пару півходів.
```

Годинники: по 10 хвилин на кожну сторону, час іде лише під час вашого ходу.

## 2. Дошка та фігури

- **Кольори** — світлі/темні поля у чотирьох темах (Класична, Дерев'яна, Океанічна, Північна).
- **Координати** a–h / 1–8 можна вимкнути в налаштуваннях.
- **Легальні ходи** — крапка на порожньому полі, кільце навколо фігури для бою.
- **Останній хід** — стрілка з поля відправлення на поле призначення.
- **Взяте** — під дошкою і над дошкою показані зняті фігури та матеріальна перевага (`+N`).
- **Підвищення пішака** — модальне вікно з вибором Q / R / B / N.
- **Перевертання дошки** — кнопка ⇅ у шапці (працює лише візуально, ви завжди білі).

## 3. Панелі — згори вниз

Права колонка — це те, що двигун «думає» про поточну позицію. Усі панелі оновлюються
після кожного ходу (`window.__subit.render()`).

### Статус

`Нова гра` / `Хід білих` / `Хід чорних` / `Двигун думає...` + підпис з додатковим станом
(шах, мат, нічия, причина завершення).

### Морфологічний стан `S₀ = I × Z × Φ`

Три осі контексту позиції (doc 01):

| Вісь | Що означає | Типові значення |
|---|---|---|
| `I · initiative` | хто має ініціативу | `ATTACK`, `PRESSURE`, `DEFENCE`, `QUIET` |
| `Z · zone` | де відбувається боротьба | `KING`, `CENTER`, `GLOBAL` |
| `Φ · phase` | стадія партії | `OPENING`, `MIDDLEGAME`, `TACTICAL`, `ENDGAME` |

Ключ `S = (I, Z, Φ)` — поточна клітинка морфологічної сітки.

Під ключем — чотири числа бюджету:

- `τ tactical` — тактична напруга (0…1);
- `complexity` — складність позиції (0…1);
- `uncertainty` — невизначеність оцінки (0…1);
- `risk` — ризик лінії (`low` / `medium` / `high`).

### Оцінка `E(SVF) vs score`

- `E · SVF` — структурна (позиційна) оцінка в пішаках, з погляду білих.
- `score · пошук` — результат пошуку в сотих пішака.
- Смуга під ними — тангенсоподібна шкала: 50% = рівно, вправо — краще за білих.

Це два різні числа за призначенням: `E(SVF)` відповідає «що варта сама позиція»,
`score` — «що варта найкраща лінія». Розбіжність між ними — привід подивитися на
тактику, а не на структуру.

### SVF-компоненти `V(P) = (M,K,A,D,C,T,Q,R,X)`

Дев'ять осей у центипешках, з погляду сторони, що ходить. Кожна вісь отримує вердикт
Белнапа: `T` (true, > +15), `F` (false, < −15), `N` (neither).

| Вісь | Панель | зміст |
|---|---|---|
| `M` | матеріал | матеріал + бонус за пару слонів |
| `K` | король | безпека власного короля проти ворожого |
| `A` | активність | мобільність, пішаки «на виході», відкриті/напіввідкриті вертикалі, контроль центру |
| `D` | оборона | організація захисту (щит короля, оборонні ресурси) |
| `C` | координація | зв'язність власних пішаків |
| `T` | тактика | **потенціал**: висячі фігури, зв'язки, вилки |
| `Q` | простір | контроль простору, просунуті пішаки |
| `R` | відношення | структурні відношення (doc 02) |
| `X` | перетворення | прохідні пішаки та їхній потенціал просування |

`Інтеграл E` — зважена сума осей (це і є `E · SVF`).

> `T` — саме *потенціал* тактики, а не вже виграний матеріал: doc 09 §4.5 забороняє
> подвійний рахунок між структурою та пошуком.

### Структурні плани `Pareto`

Генератор планів (doc 11) пропонує структурні цілі — наприклад «зайняти відкриту
вертикаль», «посилити щит короля», «провести пішака», «поміняти активну фігуру».
Кожен план показує:

- **назву** і теги стану: `ok` — виконується, `no` — не виконується;
- **ходові** — конкретні поля/фігури, що реалізують план;
- **вартість/пріоритет** — наскільки план дешевий і важливий.

Плани, що залишилися після відбору за Парето, використовуються і в порядку ходів пошуку
(на структурному рівні, **попід** тактики: бонус плану обмежений `[0, 1]`, тому план ніколи
не перебиває взяття).

### Відношення та критичність `R(P)`

- кількість структурних відносно кожного типу (doc 02);
- список найкритичніших полів — там, де відношення сходяться, тобто де позиція
  «тримається» або «ламається».

### Пошук `α-β + TT`

`score`, `depth`, `seldepth`, `nodes`, `nps`, `risk`, `PV` (головна лінія в SAN).
Це дані останнього **завершеного** ітераційного поглиблення: якщо пошук не встиг,
числа не змішуються з попередньою ітерацією.

### Історія ходів

Пара «номер — хід білих — хід чорних» у SAN, з підсвіткою останнього ходу.

### Керування

⚡ Нова гра · ↶ Скасувати · 💡 Підказка · 🏳 Здатися, і нижче — пігулки рівнів 1–5.

## 4. Кнопки в шапці

| Кнопка | Дія |
|---|---|
| `?` | Довідка — коротка інструкція + таблиця панелей |
| `Ƒ` | FEN — показати поточну позицію, вставити свою, скопіювати |
| `⇅` | Перевернути дошку |
| `↓` | Експорт PGN поточної партії |
| `⚙` | Налаштування |

Індикатор `main thread` показує, що пошук виконується в тому ж потоці (Web Worker у v3
не використовується).

## 5. Керування грою

| Дія | Як |
|---|---|
| Зробити хід | клік по фігурі → клік по підсвіченому полю |
| Зробити хід (альтернатива) | перетягнути фігуру на поле |
| Скасувати хід | ↶ Скасувати (відкочує ваш хід і відповідь двигуна) |
| Підказка | 💡 Підказка — двигун показує свій варіант за вас |
| Здатися | 🏳 Здатися — партія завершується поразкою |
| Нова партія | ⚡ Нова гра або ⚙ → нова гра з FEN |
| Завершення | статус показує `Мат`, `Пат`, `Нічия` (50 ходів / повторення) або іншу причину |

Партія завершується автоматично: мат, пат, 75-й хід, п'ятикратне повторення. Мат і
нічия за 50 ходів / трикратне повторення — «claimable»: у грі вони не завершують партію
примусово, якщо ви не заявляєте нічию.

## 6. Рівні складності

Пігулки `1 Поч · 2 Лег · 3 Сер · 4 Скл · 5 Експ` задають глибину пошуку:

| Рівень | Глибина | Годинник-запобіжник |
|---|---|---|
| 1 · Початківець | 1 | — |
| 2 · Легкий | 2 | — |
| 3 · Середній (за замовчуванням) | 4 | — |
| 4 · Складний | 6 | — |
| 5 · Експерт | 8 | 2.5 с на хід |

Глибина — це жорсткий ліміт; годинник лише не дає глибокому пошуку заморозити сторінку.
Рівень можна змінити й у ⚙ налаштуваннях.

## 7. Налаштування

| Параметр | Значення |
|---|---|
| Тема дошки | Класична · Дерев'яна · Океанічна · Північна |
| Координати | Так / Ні |
| Підсвітка ходів | Так / Ні |
| Стрілка останнього ходу | Так / Ні |
| Рівень гри | 1–5 |
| Режим оцінки | `fast` (без структури) · `structural` (SVF) |

Режим оцінки впливає на те, яку оцінку показує панель `Оцінка` та як двигун рахує
позицію: `fast` — швидкий tier (матеріал, PST, мобільність, пішакові структури),
`structural` — SVF-вектор. Пошук завжди отримує узгоджену з боку сторони, що ходить,
оцінку (це критично: саме з цим пов'язана головна виправлена помилка v3, коли вузли
за чорних оцінювалися з протилежним знаком).

## 8. FEN та PGN

- `Ƒ` → «Показати поточну позицію»: поле з FEN, кнопки **Копіювати** та **Завантажити**.
- Вставте FEN у поле і натисніть **Завантажити** — партія почнеться з цієї позиції.
- `↓` завантажує `subit-chess-<дата>.pgn` з усіма ходами партії.

> Якщо FEN задає хід чорних, ви все одно граєте білими: ви можете ходити лише білими,
> а двигун — лише чорними.

## 9. Консольний API

`window.__subit` — той самий handle, що використовує DOM-тест:

```js
__subit.fen                  // поточний FEN
__subit.history              // масив ходів (об'єкти з uci/san)
__subit.move('e2e4')         // зробити хід UCI → true/false
__subit.analyze()            // повний зріз: context, vector, plans, eval, meta
__subit.engine               // екземпляр Engine
__subit.engine.search({ depth: 6 })   // { move, uci, san, score, depth, nodes, nps, pv, pvSan, risk, ... }
__subit.engine.perft(4)      // 197281
__subit.engine.selfPlay(40)  // партія «двигун проти себе» у пам'яті
__subit.setLevel(4)          // рівень складності
__subit.newGame('FEN')       // нова партія з позиції
__subit.render()             // перемалювати дошку й панелі
```

Приклад — глибокий аналіз позиції:

```js
const r = __subit.engine.search({ depth: 8 });
console.log(r.san, r.score, r.depth, r.nodes, r.pvSan.join(' '));
```

## 10. Що означають числа в панелях

- **Оцінка в пішаках.** `+0.35` = білі кращі приблизно на третину пішака. `±10.00` і
  більше — практично вирішена позиція (не обов'язково мат).
- **Вердикти `T/F/N`** — не «добре/погано», а «вісь виражена / не виражена / нейтральна»
  відносно порогу ±15 cp.
- **`score` vs `E(SVF)`** — якщо пошук каже одне, а структура інше, дивиться на тактику:
  структурна оцінка не бачить форсованих варіантів.
- **Глибина vs `seldepth`** — `depth` — ітерація, `seldepth` — максимальна глибина з
  урахуванням розширень (шах, взяття). `seldepth` > `depth` — нормально.
- **`risk`** — оцінка надійності лінії (doc 29/35): `low` / `medium` / `high`.
- **Плани `ok/no`** — виконується план чи ні *зараз*; план може бути ще не виконаний, але
  залишатися правильним курсом.

## 11. Типові проблеми

| Симптом | Причина / рішення |
|---|---|
| Дошка не реагує на клік | Ви граєте білими; якщо хід чорних — зачекайте. Після завершення партії потрібна ⚡ Нова гра. |
| Пошук «завис» на рівні 5 | Рівень 5 має запобіжник 2.5 с. Якщо браузер усе одно не відповідає — знизьте рівень. |
| Панелі показують `—` | `analyze()` не зміг прочитати позицію: завантажте коректний FEN (6 полів). |
| Усі оцінки виглядають «з перевернутим знаком» | Перевірте режим оцінки в ⚙: `fast`/`structural` мусить бути однаковим для всіх панелей. |
| PGN не експортується | Експорт доступний лише після першого ходу в партії. |
| Ходів немає, а партія не закінчилась | 50-й хід / трикратне повторення — claimable: потрібна заява; автоматично партію завершують 75-й хід і п'ятикратне повторення. |

Повний опис пошуку та оцінки: `docs/theory/05` (пошук), `09` (SVF), `11` (плани),
`25` (абляції), `31`–`33`, `36`.

## 12. Глосарій

| Термін | Значення |
|---|---|
| **SVF** | Structural Value Function — вектор `V(P) = (M,K,A,D,C,T,Q,R,X)` |
| **S₀** | морфологічний стан `(I, Z, Φ)` — ініціатива, зона, фаза |
| **Pareto** | відбір планів, що не домінуються іншими за (вартість, важливість) |
| **TT** | transposition table — кеш уже порахованих позицій |
| **PV** | principal variation — головна лінія, яку обрав пошук |
| **seldepth** | глибина з розширеннями (селективна) |
| **LMR** | late move reductions — зменшення глибини для пізніх тихих ходів |
| **null move** | «пропуск ходу» для швидкого відкидання програшних ліній |
| **aspiration** | пошук у вузькому вікні навколо очікуваної оцінки |
| **claimable draw** | нічия, яку треба заявити (50 ходів, трикратне повторення) |
| **automatic draw** | нічия, що настає автоматично (75 ходів, п'ятикратне повторення) |
| **cp** | centipawns — сота пішака (100 cp = 1 пішак) |
| **ablation** | вимірювання внеску компонента: конфігурація з вимкненим шаром проти базової |
