## FD-05 — CHESS GRADIENT OPERATOR

**Специфікація:** SC-FD-001-FD05  
**Версія:** 0.5.0  
**Батьківський компонент:** FIELD DYNAMICS  
**Попередній документ:** FD-04 — DIRECTIONAL INFLUENCE OPERATORS  
**Наступний документ:** FD-06 — DIVERGENCE OPERATOR  
**Пріоритет:** P0  
**Статус:** DRAFT — формальна специфікація, не реалізовано та не верифіковано в коді двигуна.

# 1. Призначення

FD-01 визначив принцип перенесення структур векторного аналізу до шахової системи.

FD-02 сформував онтологію шахових структурних полів.

FD-03 визначив дискретне векторне представлення впливів.

FD-04 сформував систему операторів аналізу напрямлених відношень.

FD-05 вводить дискретний градієнт — оператор, який визначає локальну зміну вибраної скалярної характеристики шахового поля між просторово суміжними клітинами.

Основне питання:

**Як визначити, у якому напрямку та наскільки швидко змінюється певна характеристика шахової позиції в межах дискретного простору дошки?**

Наприклад, недостатньо знати, що білий бік атакує шість клітин центральної області.

Необхідно мати можливість визначити:

- де концентрація атак зростає;
- де вона зменшується;
- між якими сусідніми клітинами виникає найбільша різниця;
- у яких напрямках відбувається зміна;
- чи формується локальна зона концентрації;
- чи існує просторовий перехід від контрольованої області до неконтрольованої;
- як змінюється структура після виконання конкретного ходу.

Градієнт надає для цього математичний інструмент.

Проте є принципове обмеження.

У шахах не існує одного природного універсального скалярного потенціалу, з якого можна обчислити всі характеристики позиції.

Атака, захист, мобільність, доступність, контроль і стратегічна оцінка мають різну семантику.

Тому FD-05 вводить не один універсальний градієнт позиції, а систему типізованих дискретних градієнтів.

Основний принцип:

**NO GRADIENT WITHOUT A DEFINED SCALAR FIELD.**

Градієнт може бути обчислений лише після того, як визначено:

1. Скалярну характеристику.
2. Її значення на клітинах або вузлах простору.
3. Семантику та одиницю вимірювання.
4. Структуру просторового сусідства.
5. Правила обробки невідомих і недоступних значень.
6. Орієнтацію напрямлених зв'язків.

# 2. Математична постановка

## 2.1. Від векторного поля до скалярного поля

FD-03 і FD-04 описують напрямлені відношення між фігурами та клітинами.

Однак класичний градієнт визначається для скалярної функції.

Тому FD-05 вводить проміжний етап — побудову скалярного представлення вибраного типу шахового впливу.

Нехай:

Q — множина клітин шахової дошки.

S — конкретний шаховий стан.

τ — тип характеристики.

c — сторона або канал впливу.

Тоді скалярне поле:

φ(q | S, τ, c)

визначає значення вибраної характеристики на клітині q у стані S.

Наприклад:

φ_attack(q | S, WHITE)

може означати кількість білих фігур, що геометрично атакують клітину q.

Інші приклади:

φ_defense(q | S, BLACK)

— кількість чорних фігур, які геометрично захищають відповідну клітину.

φ_mobility(q | S, WHITE)

— характеристика просторової мобільності білих фігур, визначена окремою проєкцією.

φ_accessibility(q | S, BLACK)

— показник доступності клітини для чорних фігур за визначеною моделлю.

Усі ці поля мають різну семантику.

Їхні градієнти не можна автоматично об'єднувати.

## 2.2. Скалярне поле як проєкція

Скалярне поле будується через типізовану проєкцію:

φ = Πτ,c(F(S))

Де:

F(S) — сукупність первинних структурних полів FD-03;

Πτ,c — оператор проєкції, який вибирає визначену характеристику;

φ — результат проєкції.

Наприклад, із множини напрямлених відношень ATTACK можна отримати кількість окремих джерел атаки для кожної клітини.

Важливо:

Проєкція повинна бути формально визначеною.

Не допускається довільне перетворення різнорідних полів на числові значення без задекларованої семантики.

## 2.3. Типізація скалярного поля

Кожне скалярне поле повинно містити:

ScalarField = (
field_id,
field_type,
side,
value_domain,
scale,
semantics,
position_id,
projection_id,
values,
validity,
provenance
)

Де:

field_id — ідентифікатор поля;

field_type — тип вихідного структурного поля;

side — WHITE, BLACK, SHARED або спеціально визначений канал;

value_domain — область числових значень;

scale — шкала;

semantics — пояснення того, що означає число;

position_id — ідентифікатор шахового стану;

projection_id — ідентифікатор способу побудови;

values — значення на вузлах;

validity — статус кожного значення;

provenance — походження даних.

# 3. Простір, на якому визначається градієнт

## 3.1. Необхідність вибору структури сусідства

У неперервному просторі градієнт визначається через локальні зміни функції за координатами.

На шаховій дошці простір дискретний.

Кожна клітина має скінченну кількість сусідів.

Тому для визначення градієнта необхідно спочатку встановити, які саме клітини вважаються суміжними.

FD-05 вводить окремий об'єкт:

GradientDomain.

Він визначає:

- множину вузлів;
- множину зв'язків між вузлами;
- напрямок кожного зв'язку;
- вагу або довжину зв'язку;
- правила включення вузлів;
- контекст застосування.

## 3.2. Основна область

Базова множина вузлів:

V = Q

Тобто кожна клітина шахової дошки є вузлом градієнтної області.

Однак множина ребер може відрізнятися залежно від типу операції.

Вводяться три базові структури.

## 3.3. G4 — ORTHOGONAL GRID

У G4 сусідами є клітини, які мають спільну сторону.

Для клітини q=(x,y):

N4(q) = {
(x+1,y),
(x−1,y),
(x,y+1),
(x,y−1)
}

із виключенням клітин, що не належать дошці.

Ця структура підходить для аналізу:

- ортогональної зміни полів;
- просторових переходів уздовж горизонталей;
- вертикальних переходів;
- локальної структури контролю по горизонталі та вертикалі.

## 3.4. G8 — KING-NEIGHBORHOOD GRID

У G8 враховуються всі вісім суміжних клітин.

N8(q) = N4(q) ∪ Ndiag(q)

де Ndiag містить чотири діагональні сусіди.

Ця структура придатна для аналізу:

- локального просторового розподілу;
- діагональних змін;
- суміжності клітин у загальній геометрії шахової дошки;
- локальних зон концентрації.

Використання G8 не означає, що всі фігури можуть переходити між усіма цими клітинами.

Це геометрична структура сусідства, а не модель легальних ходів.

## 3.5. G_piece — PIECE-DEPENDENT GRAPH

Окремий клас становлять графи, побудовані за відношеннями конкретного типу фігури.

Наприклад:

G_rook — структура ортогональних зв'язків тури;

G_bishop — структура діагональних зв'язків слона;

G_knight — структура стрибкоподібних зв'язків коня.

Ці графи використовуються тоді, коли потрібен градієнт на спеціально визначеній структурі переміщення або доступності.

Не можна підміняти ними загальну геометрію дошки.

## 3.6. Незалежність геометрії від легальності

Ребро в градієнтній області означає, що два вузли пов'язані відповідно до обраної математичної структури.

Воно не означає, що фігура може виконати легальний хід між ними.

Наприклад, клітини d4 і e4 суміжні в G4 незалежно від того:

- чи зайнята e4;
- чи контролюється e4 суперником;
- чи має будь-яка фігура право перейти на e4.

Градієнт характеризує зміну скалярного поля між вузлами, а не допустимість шахового переходу.

# 4. Формальне визначення дискретного градієнта

## 4.1. Орієнтоване ребро

Нехай:

G=(V,E)

— вибраний граф градієнтної області.

Для кожного ребра визначається орієнтація:

e=(u,v)

де u — початковий вузол, v — кінцевий вузол.

Орієнтація є математичною домовленістю.

Вона не повинна залежати від кольору фігур або сторони, що ходить.

## 4.2. Дискретна різниця

Для скалярного поля φ визначається:

Dφ(e) = φ(v) − φ(u)

Це основна дискретна різниця поля вздовж ребра.

Якщо:

φ(u)=2

φ(v)=5

тоді:

Dφ(e)=3

Це означає, що значення характеристики зросло на три одиниці під час переходу від u до v.

Якщо:

φ(u)=5

φ(v)=2

тоді:

Dφ(e)=−3

Значення характеристики зменшилося на три одиниці.

Якщо:

φ(u)=φ(v)

тоді:

Dφ(e)=0.

Це означає відсутність зміни вибраної числової характеристики між цими вузлами.

Воно не означає відсутності шахового впливу.

## 4.3. Градієнт на ребрі

Нехай:

ℓ(e) — довжина ребра відповідно до обраної метрики.

Тоді зважений дискретний градієнт:

Gradφ(e) = (φ(v) − φ(u)) / ℓ(e)

Якщо використовується незважена графова модель, можна застосовувати:

Gradφ(e) = φ(v) − φ(u)

Ці два варіанти не повинні змішуватися.

Перший враховує довжину ребра.

Другий вимірює зміну на один графовий перехід.

Для шахової дошки обидва підходи можуть бути коректними за умови, що вибір метрики зафіксований у конфігурації оператора.

## 4.4. Орієнтаційна властивість

Якщо напрямок ребра змінити:

e'=(v,u)

тоді:

Dφ(e') = −Dφ(e)

Це фундаментальна властивість дискретного градієнта.

Вона повинна виконуватися для всіх допустимих числових полів.

# 5. Метрика шахового простору

## 5.1. Необхідність окремої метрики

На шаховій дошці ортогональні та діагональні переходи мають різну геометричну довжину в евклідовому представленні.

Ортогональна довжина:

ℓ₄ = 1

Діагональна довжина за евклідовою метрикою:

ℓ₈ = √2

Однак використання √2 не є обов'язковим для кожного типу аналізу.

## 5.2. METRIC_GRID

Для G4:

кожне ребро має довжину 1.

Це природна модель для аналізу ортогональних переходів.

## 5.3. METRIC_EUCLIDEAN_GRID

Для G8:

- ортогональне ребро має довжину 1;
- діагональне ребро має довжину √2.

Це дозволяє оцінювати зміну характеристики з урахуванням геометричної довжини переходу.

## 5.4. METRIC_GRAPH

Кожне ребро має довжину 1 незалежно від його координатної довжини.

Ця модель аналізує зміну на один структурний перехід.

## 5.5. PIECE_METRIC

Для спеціальних графів може бути визначена окрема метрика.

Наприклад, граф коня може трактувати кожен стрибок як один перехід незалежно від координатної відстані.

Ця модель не повинна автоматично ототожнюватися з евклідовою геометрією.

## 5.6. Вимога FD05-M001

Кожен результат градієнта повинен містити ідентифікатор метрики.

Не допускається порівнювати числові градієнти, отримані за різними метриками, як безпосередньо еквівалентні.

# 6. Скалярні характеристики, придатні для градієнтного аналізу

FD-05 не дозволяє застосовувати градієнт безпосередньо до будь-якої інформації, що міститься в шаховій позиції.

Необхідно визначити допустимі проєкції.

## 6.1. ATTACK COUNT FIELD

Для сторони c:

φ_attack(q,c,S)

визначає кількість унікальних фігур сторони c, які геометрично атакують q.

Приклад:

φ_attack(e4,WHITE,S)=3

означає, що три різні білі фігури геометрично атакують e4.

Тоді градієнт дозволяє визначати, як змінюється концентрація атак між суміжними клітинами.

Важливо:

Це геометрична характеристика.

Вона не дорівнює тактичній цінності атак.

## 6.2. DEFENSE COUNT FIELD

Визначається:

φ_defense(q,c,S)

Воно відображає кількість джерел геометричної підтримки або захисту відповідно до чітко визначеної семантики проєкції.

Необхідно окремо визначити, чи враховується:

- геометричний захист клітини;
- захист фігури;
- можливість легального повторного взяття;
- тактична безпека.

Для базової версії FD-05 рекомендовано використовувати лише геометричну характеристику.

## 6.3. ATTACK-DEFENSE SEPARATION

Білий attack count і білий defense count не повинні автоматично зливатися.

Так само не можна без окремого оператора віднімати чорний attack count від білого.

Рекомендується будувати чотири незалежні поля:

φ_attack_WHITE

φ_attack_BLACK

φ_defense_WHITE

φ_defense_BLACK

Це дозволяє обчислити чотири незалежні градієнти.

## 6.4. MOBILITY DENSITY FIELD

Можна визначити поле просторової мобільності, якщо створено формальне правило проєкції мобільності фігур на клітини.

Наприклад, воно може відображати кількість фігур певної сторони, для яких клітина є доступною ціллю за заданою моделлю.

Але перед обчисленням градієнта необхідно встановити, чи використовується:

- геометрична мобільність;
- псевдолегальна мобільність;
- легальна мобільність.

Ці три варіанти мають різні результати.

## 6.5. ACCESSIBILITY FIELD

Можна створювати окрему скалярну характеристику доступності клітин.

Наприклад:

φ_accessibility(q,c,S)

може відображати кількість фігур сторони c, для яких q є доступною ціллю за визначеними правилами.

У цьому випадку необхідно зберігати:

- тип фігур;
- правила доступності;
- факт блокування;
- контекст;
- provenance.

## 6.6. STRUCTURAL VALUE FIELD

У майбутньому може бути визначене скалярне поле стратегічної значущості клітин.

Але воно повинно надходити від окремого компонента оцінювання.

Наприклад:

φ_structural_value(q,S)

може відображати оцінку структурної важливості клітини.

FD-05 не повинен самостійно визначати формулу цієї оцінки.

Він лише обчислює дискретну зміну вже визначеної характеристики.

## 6.7. Заборонені проєкції без додаткової формалізації

Не можна безпосередньо застосовувати градієнт до:

- категоріального статусу клітини;
- невизначеного конфлікту;
- списку фігур;
- множини можливих ходів;
- неупорядкованих структурних зв'язків;
- комбінованого значення різних типів полів.

Для таких даних спочатку потрібна окрема числова проєкція зі встановленою семантикою.

# 7. Оператор GR-01 — SCALAR FIELD EXTRACTION

## 7.1. Призначення

GR-01 формує скалярне поле з первинних структурних даних.

Він є обов'язковим попереднім етапом перед будь-яким обчисленням градієнта.

## 7.2. Вхідні дані

- шаховий стан S;
- структурні відношення FD-03;
- тип поля;
- сторона;
- тип числової характеристики;
- параметри проєкції.

## 7.3. Алгоритм

1. Визначити тип структурного поля.
2. Вибрати відповідні первинні відношення.
3. Згрупувати їх за цільовими клітинами.
4. Перевірити унікальність джерел.
5. Обчислити вибрану числову характеристику.
6. Зберегти статус кожного значення.
7. Зберегти provenance.
8. Прив'язати результат до конкретного шахового стану.
9. Перевірити семантичну однорідність значень.

## 7.4. Результат

ScalarField.

## 7.5. Приклад

Нехай клітина d4 атакована трьома білими фігурами.

Тоді:

φ_attack(d4,WHITE,S)=3

Якщо e4 атакована двома білими фігурами:

φ_attack(e4,WHITE,S)=2

GR-01 не робить висновку, що d4 стратегічно важливіша за e4.

Він лише створює числову проєкцію геометричного поля атак.

# 8. Оператор GR-02 — EDGE DIFFERENCE

## 8.1. Призначення

GR-02 визначає локальну різницю значень скалярного поля між двома суміжними вузлами.

Це базова дискретна операція FD-05.

## 8.2. Математичне визначення

Для ребра:

e=(u,v)

обчислюється:

Δφ(e)=φ(v)−φ(u)

Результат має знак.

Позитивне значення означає збільшення поля від u до v.

Негативне — зменшення.

Нульове — однакові значення.

## 8.3. Орієнтація

Орієнтація ребра повинна бути визначена однозначно.

Для стандартної координатної моделі можна прийняти:

- східне ребро: від меншого x до більшого x;
- північне ребро: від меншого y до більшого y;
- діагональні ребра — за лексикографічним порядком координат або іншим зафіксованим правилом.

Вибір правила впливає на знак результату, але не на абсолютну різницю.

## 8.4. Формат результату

GradientEdgeValue = (
edge_id,
source_node,
target_node,
raw_difference,
edge_length,
gradient_value,
orientation,
field_id,
context_id,
validity,
provenance
)

## 8.5. Заборона семантичного змішування

Різниця між attack count і mobility count не є валідною операцією GR-02.

Один оператор може порівнювати лише значення одного сумісного скалярного поля.

# 9. Оператор GR-03 — WEIGHTED DISCRETE GRADIENT

## 9.1. Призначення

GR-03 враховує довжину ребра та визначає зміну характеристики на одиницю вибраної метрики.

## 9.2. Визначення

Для орієнтованого ребра e=(u,v):

Gradφ(e)=Δφ(e)/ℓ(e)

де ℓ(e)>0.

## 9.3. Приклад

Нехай:

φ(u)=2

φ(v)=5

Для ортогонального переходу:

ℓ(e)=1

Gradφ(e)=3

Для діагонального переходу за евклідовою метрикою:

ℓ(e)=√2

Gradφ(e)=3/√2

Отримані значення описують різницю з урахуванням вибраної геометричної довжини.

Однак вони належать до різних контекстів метрики.

## 9.4. Числова точність

Для базової шахової моделі значення можуть бути цілочисельними.

Якщо використовується √2, необхідно визначити числовий формат.

Рекомендується:

- зберігати точну або раціональну форму там, де це можливо;
- не округлювати проміжні результати без потреби;
- визначити допустиму похибку для тестів;
- не використовувати нестабільні порівняння floating-point як єдиний механізм перевірки рівності.

Для першої реалізації можна також обмежитися METRIC_GRAPH, де кожне ребро має одиничну довжину.

---

# 10. Оператор GR-04 — LOCAL DIRECTIONAL GRADIENT

## 10.1. Призначення

GR-02 і GR-03 визначають градієнт на ребрі.

GR-04 формує локальне напрямлене представлення змін скалярного поля навколо конкретної клітини.

Це важливо для переходу від реберних характеристик до векторного представлення градієнта.

## 10.2. Центральні різниці

Для внутрішньої клітини q=(x,y), якщо доступні симетричні сусіди:

gₓ(q) = [φ(x+1,y)−φ(x−1,y)]/2

gᵧ(q) = [φ(x,y+1)−φ(x,y−1)]/2

Отримуємо локальне представлення:

Grad_local φ(q) = (gₓ,gᵧ)

Ця формула відповідає центральній різниці на ортогональній сітці з одиничним кроком.

Важливо: вона має застосовуватися лише тоді, коли всі необхідні значення валідні.

## 10.3. Односторонні різниці

На межах дошки симетричний центральний розрахунок може бути неможливим.

Для східної межі, наприклад, не існує клітини x+1.

Тому можуть використовуватися односторонні різниці.

У напрямку зростання x:

gₓ(q)=φ(x+1,y)−φ(x,y)

У напрямку зменшення x:

gₓ(q)=φ(x,y)−φ(x−1,y)

Аналогічно для y.

Використаний метод повинен бути позначений у результаті.

Не можна підставляти нуль для неіснуючого сусіда.

## 10.4. Неповні дані

Якщо один із необхідних вузлів має статус UNKNOWN, відповідна похідна не може автоматично обчислюватися.

Можливі результати:

VALID

PARTIAL

UNDEFINED

OUT_OF_DOMAIN

STALE

Для PARTIAL повинно бути зазначено, які компоненти були отримані, а які залишилися невизначеними.

## 10.5. Результат

LocalGradient = (
node_id,
gradient_x,
gradient_y,
method,
domain_id,
metric_id,
field_id,
validity,
context,
provenance
)

# 11. Оператор GR-05 — GENERALIZED LOCAL GRADIENT

## 11.1. Призначення

Цей оператор узагальнює локальне обчислення для випадків, коли:

- використовується G8;
- кількість сусідніх вузлів відрізняється;
- граф має нерегулярну структуру;
- використовується piece-dependent graph;
- напрямки не збігаються з ортогональними координатними осями.

## 11.2. Проблема реконструкції

На кожному ребрі відома різниця:

Δφ(e)=φ(v)−φ(u)

Але навколо вузла може бути більше двох напрямків.

Тому виникає задача оцінити локальний вектор g, який найкраще описує ці зміни.

## 11.3. Метод найменших квадратів

Нехай q — центральний вузол.

Для кожного сусіда qᵢ визначається:

δᵢ = qᵢ − q

та:

Δᵢ = φ(qᵢ)−φ(q)

Шукається вектор g, який мінімізує:

Σ wᵢ (g·δᵢ − Δᵢ)²

де wᵢ — ваги ребер або сусідів.

Результат:

g(q)=argmin Σ wᵢ (g·δᵢ−Δᵢ)²

Це дозволяє отримати найкраще локальне лінійне наближення скалярного поля.

## 11.4. Умови визначеності

Рішення повинно бути достатньо визначеним за геометрією доступних сусідів.

Якщо всі сусіди лежать на одній лінії, неможливо повністю відновити двовимірний градієнт.

У такому випадку результат повинен бути:

RANK_DEFICIENT

або містити лише визначену компоненту.

Не можна повертати довільний повний вектор.

## 11.5. Уникнення зайвої складності

GR-05 не є обов'язковим для першої реалізації.

Базовий FD-05 може бути реалізований через реберні різниці GR-02 і центральні різниці GR-04.

Узагальнений оператор потрібен для наступних етапів, коли буде доведена необхідність аналізувати складніші графові структури.

---

# 12. Оператор GR-06 — GRADIENT MAGNITUDE

## 12.1. Призначення

GR-06 визначає величину локального градієнта.

Для локального координатного вектора:

g=(gₓ,gᵧ)

його евклідова норма:

|g|=√(gₓ²+gᵧ²)

Величина градієнта характеризує силу зміни вибраної скалярної характеристики в локальному наближенні.

## 12.2. Інтерпретація

Велике значення може означати:

- різкий перехід у кількості атак;
- різку зміну концентрації захисту;
- локальну зміну доступності;
- значну різницю структурних характеристик між сусідніми областями.

Проте велика величина градієнта не означає автоматично:

- тактичну небезпеку;
- стратегічну перевагу;
- необхідність негайного ходу;
- високу матеріальну цінність клітини.

Це лише характеристика зміни конкретного скалярного поля.

## 12.3. Норма залежить від метрики

Норма локального градієнта повинна відповідати метриці, у якій він побудований.

Результати, отримані в G4, G8 та PIECE_METRIC, не можна механічно порівнювати без узгодження метрики.

---

# 13. Оператор GR-07 — GRADIENT DIRECTION

## 13.1. Призначення

GR-07 визначає напрямок локального зростання скалярної характеристики.

Для локального градієнта:

g=(gₓ,gᵧ)

напрямок визначається в системі координат дошки.

Позитивні компоненти означають зростання характеристики відповідно до додатного напрямку координати.

Наприклад:

gₓ>0 — значення зростає на схід;

gₓ<0 — значення зростає на захід;

gᵧ>0 — значення зростає на північ;

gᵧ<0 — значення зростає на південь.

Якщо обидві компоненти ненульові, напрямок визначається їхньою комбінацією.

## 13.2. Нульовий градієнт

Якщо:

g=(0,0)

напрямок зростання не визначений.

Результат:

NO_PREFERRED_GRADIENT_DIRECTION.

Це не означає, що поле не існує.

Це означає лише, що локальна оцінка зміни не визначає переважного напрямку.

## 13.3. Важливе обмеження

Напрямок градієнта не є рекомендованим шаховим ходом.

Якщо attack count зростає на схід, це не означає, що фігура повинна рухатися на схід.

Градієнт показує просторовий напрямок зростання характеристики.

Легальність, тактична безпека та стратегічна доцільність належать до інших компонентів.

---

# 14. Двоканальна градієнтна модель

## 14.1. Незалежні поля сторін

У FD-03 і FD-04 було встановлено необхідність зберігати WHITE та BLACK в окремих каналах.

FD-05 зобов'язує дотримуватися цього принципу.

Для атак:

Gradφ_attack_WHITE

Gradφ_attack_BLACK

Для захисту:

Gradφ_defense_WHITE

Gradφ_defense_BLACK

Кожен градієнт обчислюється окремо.

## 14.2. Чому не можна одразу віднімати поля

Припустимо:

φ_attack_WHITE(q)=3

φ_attack_BLACK(q)=3

Їхня різниця:

3−3=0.

Проте це не означає відсутності впливу.

На клітині можуть одночасно існувати три білі та три чорні геометричні атаки.

Тому FD-05 не повинен за замовчуванням створювати єдине поле:

φ_total = φ_WHITE − φ_BLACK.

## 14.3. Дозволене контрастне поле

За потреби інший компонент може визначити:

φ_contrast(q)=φ_WHITE(q)−φ_BLACK(q).

Однак це буде окремою похідною скалярною характеристикою.

Вона повинна мати:

- окремий field_id;
- окрему семантику;
- окремий projection_id;
- provenance обох вхідних полів.

Її градієнт не замінює градієнти окремих сторін.

---

# 15. Оператор GR-08 — MULTI-SCALE GRADIENT

## 15.1. Призначення

GR-08 дозволяє досліджувати зміну скалярної характеристики на різних просторових масштабах.

Локальний градієнт описує зміну між сусідніми вузлами.

Однак шахова структура має різні масштаби:

- клітина;
- локальне оточення;
- зона;
- фланг;
- центральна область;
- вся дошка.

## 15.2. Базові масштаби

Вводяться:

MICRO — окремі клітини та їхні безпосередні сусіди;

MESO — локальні групи клітин;

MACRO — фланги, центральні та тилові зони;

META — порівняння загальної організації просторових характеристик.

Ці масштаби відповідають загальній багаторівневій логіці SUBIT.

## 15.3. Локальний масштаб MICRO

Обчислюється градієнт між сусідніми клітинами.

Це базова операція FD-05.

## 15.4. Масштаб MESO

Визначаються агреговані значення поля для структурних зон.

Наприклад:

φ_zone(Z)=середнє значення φ(q) для q∈Z.

Або:

φ_zone_sum(Z)=сума φ(q) для q∈Z.

Ці дві функції мають різну семантику.

Середнє характеризує типове значення в зоні.

Сума характеризує загальну кількість або накопичену величину відповідно до обраної шкали.

Порівнювати їх без нормалізації не можна.

Після побудови зонального скалярного поля градієнт може визначатися на графі суміжності зон.

## 15.5. Масштаб MACRO

Аналізується різниця між великими структурними областями:

- центр;
- королівський фланг;
- ферзевий фланг;
- тил;
- інші формально визначені зони.

Наприклад, можна визначити, чи зростає концентрація білих атак у напрямку королівського флангу.

Однак такий результат залежить від того, як саме визначені зони.

## 15.6. Масштаб META

META не повинен означати просто усереднення всіх попередніх результатів.

Він має зіставляти:

- різні типи полів;
- різні масштаби;
- різні контексти;
- зміни між послідовними позиціями;
- стабільність або нестабільність локальних градієнтів.

FD-05 визначає лише можливість збереження багатомасштабних градієнтних характеристик.

Повна метамодель належить до наступних рівнів архітектури SUBIT-CHESS.

---

# 16. Оператор GR-09 — GRADIENT TRANSFORMATION DELTA

## 16.1. Призначення

GR-09 визначає зміну градієнтного поля після виконання шахового ходу.

Нехай:

S₀ — початкова позиція;

m — хід;

S₁=Tₘ(S₀) — нова позиція.

Для вибраного скалярного поля:

φ₀=φ(S₀)

φ₁=φ(S₁)

Відповідно:

G₀=Grad(φ₀)

G₁=Grad(φ₁)

Зміна градієнта:

ΔG=G₁−G₀.

## 16.2. Умови порівняння

Порівняння можливе лише за умови сумісності:

- типу скалярного поля;
- семантики;
- проєкції;
- метрики;
- домену;
- структури орієнтації;
- одиниць вимірювання.

Якщо одна з цих характеристик змінилася, результат повинен бути позначений як несумісний або вимагати окремого перетворення.

## 16.3. Класи змін

Вводяться:

GRADIENT_INCREASED

Величина градієнта зросла.

GRADIENT_DECREASED

Величина градієнта зменшилася.

GRADIENT_DIRECTION_CHANGED

Змінився напрямок локального зростання.

GRADIENT_FLATTENED

Локальний градієнт наблизився до нуля.

GRADIENT_STEEPENED

Локальна зміна стала різкішою.

GRADIENT_APPEARED

Раніше невизначений або нульовий градієнт став визначеним і ненульовим.

GRADIENT_DISAPPEARED

Раніше наявний ненульовий градієнт став нульовим або втратив визначеність.

## 16.4. Відмінність зміни поля від зміни градієнта

Можлива ситуація, коли всі значення скалярного поля збільшуються на однакову константу.

Наприклад:

φ₁(q)=φ₀(q)+2

Тоді:

Grad(φ₁)=Grad(φ₀)

Градієнт не змінюється.

Отже, однакова зміна всього поля не обов'язково створює зміну градієнта.

Цю властивість потрібно використовувати в тестах.

# 17. Властивості дискретного градієнта

FD-05 встановлює математичні властивості, які повинні виконуватися незалежно від конкретної шахової позиції.

## 17.1. Інваріантність до додавання константи

Нехай:

ψ(q)=φ(q)+c

де c — однакова константа для всіх вузлів.

Тоді:

Grad(ψ)=Grad(φ).

Додавання однакового значення до кожної клітини не змінює градієнт.

## 17.2. Лінійність

Для двох сумісних скалярних полів φ та ψ:

Grad(φ+ψ)=Grad(φ)+Grad(ψ).

Для константи a:

Grad(aφ)=a·Grad(φ).

Ці властивості виконуються для лінійного дискретного оператора різниць за однакового домену та метрики.

Однак семантична сумісність полів залишається обов'язковою.

Математична лінійність не є дозволом додавати несумісні характеристики.

## 17.3. Зміна орієнтації

Для оберненого ребра:

Gradφ(v,u)=−Gradφ(u,v)

за однакової довжини ребра.

## 17.4. Градієнт константного поля

Якщо:

φ(q)=c

для всіх вузлів q у зв'язній області.

Тоді:

Gradφ=0.

## 17.5. Потенціальність і циклічні суми

Якщо градієнт отриманий із скалярного поля, сума необроблених різниць уздовж будь-якого замкненого циклу дорівнює нулю.

Для циклу:

q₀→q₁→...→qₙ=q₀

отримуємо:

Σ [φ(qᵢ₊₁)−φ(qᵢ)] = 0.

Це випливає з телескопічного скорочення послідовних різниць.

Ця властивість є важливою для майбутньої перевірки циркуляційних характеристик.

Якщо збережені реберні значення не задовольняють цю умову, вони не можуть бути точним градієнтом одного скалярного поля на відповідному циклі без додаткових пояснень.

# 18. Градієнт і графова топологія

## 18.1. Графова інтерпретація

FD-05 розглядає скалярне поле як функцію на вершинах графа.

Скалярне поле — це 0-коформа.

Його дискретна різниця на ребрах — 1-коформа.

У відповідній дискретній математичній моделі:

d₀: C⁰(V) → C¹(E)

де:

C⁰(V) — простір скалярних значень на вершинах;

C¹(E) — простір значень на орієнтованих ребрах.

Для кожного ребра:

(d₀φ)(u,v)=φ(v)−φ(u).

Це формалізує градієнт через оператор дискретної зовнішньої похідної.

## 18.2. Матриця інцидентності

Для обчислювальної реалізації можна використовувати матрицю інцидентності графа.

Нехай:

B — матриця інцидентності.

φ — вектор скалярних значень на вершинах.

Тоді:

g=Bᵀφ

за відповідної домовленості про орієнтацію та визначення матриці інцидентності.

У цьому представленні кожен елемент g відповідає одному орієнтованому ребру.

Якщо використовується матриця зворотної орієнтації, знак формули змінюється відповідно.

Для першої реалізації не обов'язково створювати повну матрицю.

Можна безпосередньо обчислювати різницю між двома значеннями.

Однак матричне представлення корисне для математичної верифікації, оптимізації та подальшої побудови операторів Лапласа.

## 18.3. Композиція з наступними операторами

У дискретній геометрії оператор дискретної зовнішньої похідної може бути застосований до скалярного поля, а наступні оператори можуть досліджувати структуру отриманих реберних значень.

Для відповідного дискретного комплексу виконується властивість:

d₁ ∘ d₀ = 0.

Тобто дискретна зовнішня похідна градієнта має нульовий результат на гранях комплексу.

Ця властивість є математичним фундаментом для подальшої формалізації дискретної циркуляції.

Водночас необхідно розрізняти:

- граф, що має лише вершини та ребра;
- клітинний комплекс, який додатково містить грані;
- конкретну метрику;
- оператори, визначені на цих структурах.

Наявність графа сама по собі ще не задає повну двовимірну теорію дискретного ротора.

# 19. Зв'язок із шаховою інтерпретацією

## 19.1. Градієнт атак

Якщо:

φ_attack_WHITE(q)

визначає кількість білих атак на клітину q, тоді градієнт показує, у якому напрямку ця кількість локально зростає або зменшується.

Наприклад:

φ(d4)=1

φ(e4)=3

Для ребра d4→e4:

Δφ=2.

Це означає, що на e4 існує на дві геометричні атаки більше, ніж на d4.

Це не доводить, що e4 вигідніше контролювати.

## 19.2. Градієнт захисту

Він може показувати просторові переходи між зонами з різною концентрацією захисних відношень.

Це дозволяє виявляти:

- локальні області сильнішої підтримки;
- ділянки з меншою кількістю джерел захисту;
- різкі зміни просторової підтримки;
- потенційні структурні розриви.

Однак геометрична кількість захистів не визначає тактичної безпеки.

## 19.3. Градієнт доступності

Він може показувати, як змінюється кількість фігур, здатних досягнути різних клітин за визначеною моделлю.

Це може бути корисним для виявлення:

- локально обмежених областей;
- відкритих зон;
- просторової асиметрії доступності;
- областей із різким зниженням мобільності.

## 19.4. Градієнт мобільності

Може характеризувати просторову неоднорідність мобільності.

Але мобільність фігури є властивістю фігури, а не автоматично властивістю кожної клітини.

Тому для її проєкції на клітини необхідно окремо визначити, що саме означає значення поля.

## 19.5. Градієнт структурної цінності

Якщо інший компонент створює скалярне поле стратегічної цінності клітин, FD-05 зможе аналізувати просторові зміни цієї оцінки.

Але для коректності необхідно:

- використовувати одну версію оцінювача;
- зафіксувати шкалу;
- зберігати параметри;
- відрізняти матеріальну оцінку від позиційної;
- не змішувати оцінки різних моделей.

**FD-06 — DIVERGENCE OPERATOR**

Отримує напрямлені реберні або локальні векторні характеристики для обчислення дискретної дивергенції.

**FD-07 — CURL / CIRCULATION**

Може використовувати реберні різниці та структурні цикли для аналізу циркуляційних властивостей.

**POSITION EVALUATION**

Може використовувати локальну неоднорідність вибраних характеристик.

**SEARCH**

Може порівнювати зміну градієнтних структур після кандидатних ходів.

## 20.5. Заборона прямого керування ходами

FD-05 не повинен самостійно генерувати рекомендації ходів.

Навіть якщо градієнт показує зростання характеристики в певному напрямку, це не гарантує, що:

- існує фігура, здатна переміститися в цей напрямок;
- відповідний хід легальний;
- ціль безпечна;
- суперник не має сильнішої відповіді;
- зміна характеристики вигідна.

Градієнт є аналітичним сигналом, а не політикою вибору ходу.

# 21. Обчислювальна складність

Нехай:

Q — кількість клітин;

E — кількість ребер вибраного графа;

S — кількість скалярних полів.

Для шахової дошки:

|Q|=64.

Для G4:

кожна клітина має не більше чотирьох сусідів.

Тому:

|E| ≤ 2·Q·2 = 4Q

якщо ребра враховуються без дублювання та з урахуванням меж дошки.

Для G8 кількість ребер також має сталу межу, пропорційну Q.

## 21.1. GR-01

Побудова скалярного поля залежить від кількості первинних відношень.

За наявності індексації:

O(R+Q).

## 21.2. GR-02

Різниця для всіх ребер:

O(E).

## 21.3. GR-03

Зважений градієнт:

O(E).

## 21.4. GR-04

Центральні та односторонні різниці:

O(Q).

## 21.5. GR-05

Локальна реконструкція методом найменших квадратів потребує невеликої системи лінійних рівнянь для кожного вузла.

Оскільки кількість сусідів обмежена, для дошки 8×8 це має невелику практичну вартість.

## 21.6. GR-06 та GR-07

Норма й напрямок:

O(Q).

## 21.7. GR-09

Порівняння двох градієнтних полів:

O(E+Q).

## 21.8. Загальна оцінка

Для фіксованої дошки всі операції FD-05 мають лінійну складність за кількістю вузлів, ребер або вхідних структурних відношень.

Основним джерелом витрат у пошуковому дереві буде не саме обчислення різниць, а повторна побудова скалярних полів із первинних структур.

Тому необхідно кешувати:

- базові attack count fields;
- defense count fields;
- доступність;
- індекси ребер;
- вибрані градієнтні профілі.

Кешування повинно бути прив'язане до конкретної позиції, проєкції, домену та метрики.

# 23. Тестова специфікація

## 23.1. Тест константного поля

Створити скалярне поле:

φ(q)=4

для всіх 64 клітин.

Очікується:

- усі реберні різниці дорівнюють нулю;
- усі визначені локальні градієнти дорівнюють нулю;
- поле має статус VALID;
- нульовий градієнт не змінює статус існування поля.

## 23.2. Тест лінійного поля

Створити:

φ(x,y)=x.

Для кожного горизонтального ребра із напрямком на схід:

Δφ=1.

Для кожного горизонтального ребра із напрямком на захід:

Δφ=−1.

Для вертикальних ребер:

Δφ=0.

Очікується коректна орієнтація.

## 23.3. Тест вертикального поля

Створити:

φ(x,y)=y.

Очікується:

- для північних ребер різниця +1;
- для південних ребер −1;
- для горизонтальних ребер 0.

## 23.4. Тест діагональної метрики

Створити поле:

φ(x,y)=x+y.

На ортогональних ребрах очікувана різниця дорівнює 1 для позитивного напрямку відповідної координати.

На діагональному переході NORTH_EAST різниця дорівнює 2.

За евклідової метрики з довжиною √2 градієнт дорівнює:

2/√2=√2.

Очікується правильне врахування метрики.

## 23.5. Тест обернення ребра

Для будь-якого ребра e=(u,v) сформувати зворотне e'=(v,u).

Очікується:

Dφ(e')=−Dφ(e).

## 23.6. Тест додавання константи

Створити два поля:

φ₁(q)

φ₂(q)=φ₁(q)+7.

Очікується однаковий градієнт для обох полів.

## 23.7. Тест лінійності

Створити два сумісні поля φ та ψ.

Обчислити градієнт їхньої суми.

Перевірити:

Grad(φ+ψ)=Grad(φ)+Grad(ψ).

## 23.8. Тест двосторонніх атак

Створити позицію, де WHITE і BLACK атакують суміжні клітини з різною кількістю джерел.

Побудувати:

Gradφ_attack_WHITE

Gradφ_attack_BLACK.

Очікується, що:

- обидва поля обчислюються окремо;
- їхні результати не згортаються;
- provenance кожного боку збережений.

## 23.9. Тест граничної клітини

Вибрати кутову клітину a1.

Очікується:

- відсутність неіснуючих сусідніх вузлів;
- використання односторонніх різниць, якщо вони доступні;
- відсутність підстановки нулів для відсутніх клітин;
- коректний статус результату.

## 23.10. Тест невідомого значення

Призначити одному вузлу статус UNKNOWN.

Спробувати обчислити градієнт на ребрі, яке його включає.

Очікується:

- невизначений результат для відповідного ребра;
- відсутність автоматичної підстановки нуля;
- збереження інформації про причину невизначеності.

## 23.11. Тест графа G4

Обчислити градієнт на ортогональній сітці.

Очікується, що діагональні ребра відсутні.

## 23.12. Тест графа G8

Обчислити градієнт на восьмисусідній сітці.

Очікується, що:

- ортогональні ребра присутні;
- діагональні ребра присутні;
- довжини визначені відповідно до метрики;
- результати з G4 не змішуються з результатами G8.

## 23.13. Тест циклічної суми

Побудувати цикл:

d4 → e4 → e5 → d5 → d4.

Згенерувати скалярне поле.

Обчислити послідовні різниці.

Очікується:

ΣΔφ=0.

## 23.14. Тест шахового ходу

Побудувати позицію S₀.

Обчислити скалярне поле та градієнт.

Виконати легальний хід і отримати S₁.

Повторно обчислити поле та градієнт.

Очікується:

- правильна зміна значень;
- правильна зміна реберних градієнтів;
- відсутність застарілих значень;
- коректна прив'язка до state_id.

## 23.15. Тест однакового підвищення поля

Збільшити значення всіх клітин на однакову константу після трансформації.

Очікується:

- зміна абсолютних значень скалярного поля;
- відсутність зміни градієнта.

Цей тест особливо важливий для перевірки правильного розділення поля та його просторової похідної.

# 24. Критерії приймання FD-05

FD-05 може бути визнаний реалізованим лише за виконання таких умов:

1. Скалярні поля мають формальні визначення.
2. Для кожного поля зафіксовано семантику.
3. Визначено підтримувані градієнтні домени.
4. Визначено підтримувані метрики.
5. Реалізовано реберну дискретну різницю.
6. Реалізовано зважений градієнт.
7. Реалізовано локальні центральні та односторонні різниці.
8. Невідомі дані не трактуються як нулі.
9. Градієнти різних сторін залишаються окремими.
10. Реалізовано перевірку орієнтаційної властивості.
11. Реалізовано перевірку інваріантності до додавання константи.
12. Реалізовано перевірку лінійності для сумісних полів.
13. Виконується властивість нульової циклічної суми для точного градієнта.
14. Граничні клітини обробляються коректно.
15. Результати мають provenance.
16. Після ходу градієнт відповідає новому шаховому стану.
17. Усі тестові сценарії проходять.
18. Результати можуть використовуватися FD-06 без втрати типів та контексту.

До виконання цих умов FD-05 залишається специфікацією.

# 25. Очікуваний результат FD-05

Після реалізації FD-05 SUBIT-CHESS отримає формальний механізм обчислення просторової зміни типізованих шахових характеристик.

Двигун зможе перейти від статичного опису:

«На клітині d4 є дві геометричні атаки, а на e4 — чотири»

до математичного опису:

«У напрямку d4→e4 значення поля геометричних атак WHITE зростає на дві одиниці».

Аналогічно можна досліджувати:

- зростання або зменшення захисної концентрації;
- просторову неоднорідність мобільності;
- зміну доступності;
- локальну зміну структурної оцінки;
- трансформацію цих характеристик після конкретного ходу.

Ключове досягнення — поява математично визначеної похідної характеристики для дискретного шахового простору.

Вона створює основу для наступних операторів векторного аналізу.

---

# 26. Висновок

FD-05 встановлює, що дискретний градієнт у SUBIT-CHESS не повинен бути механічною копією неперервної формули.

Його фундаментом є:

- скалярне поле з чіткою семантикою;
- дискретна область;
- граф суміжності;
- орієнтовані ребра;
- різниця значень;
- визначена метрика;
- правила валідності даних;
- збереження контексту й provenance.

Це забезпечує математичну коректність і не допускає змішування різнорідних характеристик позиції.

Послідовність FIELD DYNAMICS тепер має такий вигляд:

FD-01 — FUNDAMENTAL TRANSPOSITION

FD-02 — CHESS STRUCTURAL FIELD ONTOLOGY

FD-03 — VECTOR REPRESENTATION OF CHESS INFLUENCE

FD-04 — DIRECTIONAL INFLUENCE OPERATORS

FD-05 — CHESS GRADIENT OPERATOR

Наступний етап:

**FD-06 — DIVERGENCE OPERATOR.**

Центральне завдання FD-06 — визначити, як у дискретній шаховій структурі формалізувати локальний баланс напрямлених потоків векторного впливу.

Для цього потрібно буде:

1. Визначити, що в SUBIT-CHESS вважається дискретним векторним полем.
2. Відокремити вхідні та вихідні напрямлені зв'язки вузла.
3. Формально визначити дискретну дивергенцію.
4. Розрізнити джерельні, стокові та збалансовані вузли.
5. Визначити роль перешкод і меж області.
6. Встановити умови збереження потоків.
7. Перевірити відповідність оператора графовій структурі шахової дошки.

Важливе математичне уточнення для наступного етапу: дивергенція має застосовуватися до належно визначеного векторного поля на ребрах або до його еквівалентного локального представлення, а не безпосередньо до довільного скалярного поля.

**FD-05 формалізує локальну зміну характеристики. FD-06 має формалізувати баланс напрямленого впливу.**
