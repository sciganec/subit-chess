- Axis content (§3): M = material + bishop-pair bonus; A = mobility, pawns "on the way out", open/half-open files, centre control; T = POTENTIAL only (hanging pieces, pins, forks) — "doc 09 §4.5 forbids double counting between structure and search"; X = passed pawns + advance potential; C = pawn connectivity; D = king shield / defence resources.
- Plan bonus is bounded [0,1] "so a plan never overrides a capture" (§3 Plans) — plans are used in move ordering UNDER tactics.
- Search panel = last COMPLETED iteration only (no mixing with partial iteration) (§3).
- U(P) = 8 uncertainties Us,Ut,Ue,Ur,Up,Uh,Um,Uc each [0,1]; leading one starred; "none changes the score" (doc 37 §5-6, doc 45 §16).
- Search must get side-to-move-consistent eval (main v3 bug: black nodes had opposite sign) (§7).
- Draws: 50-move/3-fold claimable; 75-move/5-fold automatic (§5, §12). perft(4)=197281 (§9).
- Levels (§6): 1:d1, 2:d2, 3:d4 (default), 4:d6, 5:d10 + 6 s/move safety clock; depth is a HARD limit; clock only a guard.
- Modes: `fast` (material, PST, mobility, pawn structure) vs `structural` (SVF) (§7).
- Glossary mentions LMR, null move, aspiration, TT as engine features (§12). Default clock 10:00 each side.
(3) Concrete implementable items affecting move choice: no formulas/constants for eval. Only: (a) level->depth map above; (b) 6 s per-move cap at L5; (c) plan bonus clamp [0,1] ordered below captures (§3); (d) fast-mode ingredients list "material, PST, mobility, pawn structures" (§7). Example: after 11...O-O the same move (Kxf1) kept from d8 (score 0.0) to d11 (+135) (§6) — evidence that depth matters for scoring not move choice at that position.
(4) Explanation/verification-only: Belnap T/F/N verdicts, U(P) 8-vector display, E(SVF) vs score divergence hint, risk label (doc 29/35), plan ok/no tags, critical-fields list of R(P), claimable-draw statuses, console API (__subit.*).
